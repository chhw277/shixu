# 拾序云端方案（待部署）

核验日期：2026-11-08，Asia/Shanghai。当前应用仍为本地 1.1.0，本文件是方案，不表示已上线、已创建云资源或已发生费用。

## 已确认的约束

- 预计最多 15 人，主要在中国大陆使用。
- 每人独立账号与任务，同一账号可以在手机、电脑访问自己的数据。
- 云服务、域名、备份的目标总预算为每年约 ¥100，非每月 ¥100。
- 开发者发布一次后，各端获得新版，避免逐人发送安装包。

## 推荐交付形态

以响应式 Web / PWA 为主，电脑浏览器和手机浏览器共用同一部署。支持的平台可添加到主屏幕或安装为应用。现有 Electron 本地包保留为旧版，不会因云端发布而自动更新；推荐迁移到云端入口，若继续维护 Electron 客户端，须另行实现其更新与云账号接入。

前端发布采用版本化静态资源，入口重新验证缓存。打开应用时检查版本，当前页面有新版时提示保存后刷新；有未提交修改时不强制刷新。数据接口与旧版前端保持兼容，再移除旧字段。PWA 的服务工作线程也须使用这套更新流程，不能承诺所有已打开页面立即切换。

CloudBase 免费环境的 3,000 资源点不能直接等同于请求数，数据库、函数、存储、CDN 等共享资源池。15 人不是费用上限，操作频率、同步策略、每次查询读取的数据量才决定用量。价格、开通资格、域名绑定与发布权限以实际控制台为准。

¥100/年适合“依靠免费档起步 + 严控用量”的试运行。现有证据不足以承诺同一预算下同时拥有长期稳定生产服务、自有域名、独立自动备份和不限额使用。自有域名费用需要按所选后缀的正常续费价询价；不能只看首年价。大陆部署如使用自有域名对外提供网站，应核验备案及接入条件。

## 实施范围与顺序

1. 先建立一个 CloudBase 免费测试环境，验证实名 / 开通资格、可用登录方式、HTTPS 托管地址与正式访问条件。用移动、联通、电信网络和实际使用地点测试；达不到要求则评估替代，不先购买年套餐。
2. 增加邀请制账号，避免短信验证码的持续成本；使用平台支持的密码认证及账号恢复方式。浏览器端不保存云管理密钥。后端按认证身份限制每一条任务、清单、习惯、专注记录的读写，客户端不能指定他人身份获得权限。
3. 改造 `src/bridge.js` 的云端数据接入。当前 `saveState` 每次覆盖整份状态，不能直接改成远程覆盖同一个 JSON：这会在两台设备同时操作时丢失修改。按实体保存，带版本号、幂等操作 ID、增量变更游标和删除标记；发生同一字段冲突时保留可恢复版本并提示处理。
4. 首版优先保证在线编辑与跨设备增量同步，页面重新回到前台时拉取更新；后台增量轮询有节制地执行。先实测用量，再决定是否改用平台实时订阅。离线时明确显示不可同步，不承诺未实现的离线写入队列。
5. 手机改为单列任务列表、抽屉导航、整页详情和触屏操作。现有 `src/styles.css` 最小宽度为 1000px，需要实际改造；仅把当前 Vite 产物上传到服务器不会得到可用手机版。
6. 登录后由用户选择将本地导出 JSON 导入其云账号；导入前预览数量并备份，按原 ID 去重，不自动上传或替换所有人的数据。15 人的数据分别隔离。
7. 版本发布检查、定期可恢复备份和用量可见性一起交付。明确备份目的地与保存成本，不把同一数据库里的副本视为独立备份。不启用无预算上限的自动扩容或超额计费。

手机后台运行、锁屏提醒和准点推送另行验证。PWA 不天然具备原生客户端的后台定时能力；本次不能把“能在手机打开”表述为“已支持锁屏准点提醒”。

## 云版验收

- 两个不同账号即使伪造其他用户的任务 ID，读取、修改、删除均被服务端拒绝。
- 同账号手机与电脑交替编辑新增、完成、删除、恢复，结果一致；网络重试不重复创建任务或重复任务实例。
- 两台设备同时修改不同任务互不覆盖；同任务冲突有明确、可恢复的处理结果。
- 云端发布后，旧页面收到更新提示；未保存编辑不会因强制更新丢失。
- 360px / 390px 手机宽度可完成新增、编辑、清单切换、习惯打卡与专注，无横向整页溢出。
- 本地 JSON 导入保留任务、清单、习惯和专注历史；重复导入可控，账号之间不串数据。
- 备份可在隔离环境恢复，并有一次实际恢复记录。
- 记录多网络访问表现和代表性操作的资源消耗，再判断免费档能否持续承载 15 人。

## 上线需要的外部条件

用户自己的云账号、实名 / 开通资格，以及如使用自有域名时的域名和备案条件。登录、创建付费资源和部署发布是后续步骤。本次未要求用户向聊天发送密码或管理密钥，也没有创建或购买云资源。
